# 拿起判定优化与验证（2026-09-22）

## 已修正

- 原先把未成功匹配 SKU 的框直接丢弃，手遮挡包装时轨迹中断。现在允许未知框在 1200ms 内，满足外观相似度、尺寸、位置和无歧义条件时延续既有身份；未知框不能新建身份，不能单独确认拿起，也不会更新身份特征。
- 取消固定 500ms 观测间隔重置。连续性窗口根据此前分析帧间隔适配，限制在 700–1500ms；长停顿不会扩大自身允许范围。
- 候选时间使用 -1 表示未开始，并同步清除证据计数。拿起及放回都需要至少两次有效观测，修复长间隔清零后错误计算为超长等待的问题。
- 上抬判定同时检查归一化中心位移 >0.32、中心上移 >0.18 和底边上移 >0.18；保持 250ms 且恢复新鲜身份确认才触发。旧版纯向上移动实际上需超过 0.5 个框高才能通过总位移条件。
- 关联使用全体代价矩阵、双向歧义检查和随时间调整的位置门限，减少低帧率运动以及突然停止时断轨。
- 特征缓存仅用于已静置的确认身份；缓存结果不累加独立身份确认次数。移动时恢复特征提取。
- UI 显示具体原因，例如等待建立基准、身份恢复、上抬证据不足、跟踪暂时丢失；日志 DetectCamPickup 记录状态变化、位移、中心及底边上移量。

## 验证结果

- 原 51 项核心断言、YUV 与解码测试通过。
- 新增 28 项拿放回归断言通过，包含约 2 FPS、遮挡、unknown 超时、冲突 SKU、平移、长间隔误触发和返回桌面计时。
- assembleDebug、assembleDebugAndroidTest、lintDebug 通过。
- 新 APK 已安装到 RK3588 Android 13；实际录入库保留。
- 新的 28 项板端自动检查通过，覆盖真实 NPU 的 INT8 检测张量、FP16 576 维特征、边界输入、持久化、商品信息文件。详见 board-pickup-optimization.txt。自动测试使用合成图像，不代表真实拿放准确率。
- 实拍确认 FP16 模式下三个 SKU 都建立了静置基准，并显示原因提示。当前杂物较多画面约 2.3–2.4 FPS，抽样分析延迟约 376–509ms。
- INT8 模式约 2.5–2.7 FPS，抽样分析延迟约 346–437ms，但薯片静置时发生间歇丢失；本次恢复 FP16，不将 INT8 设为默认。

## 仍需现场复测

当前未取得本轮完整的真实拿起/放回动作证据，不能声称已通过拿放准确率验收。请等界面三件商品静置基准就绪后，依次拿起、保持约两秒并放回，同时检查 DetectCamPickup 日志。

本次仍是单目运动推断，没有手部模型和深度信息。向桌面远处平移可能具有相同的投影运动，完全遮挡和快出画仍可能丢失。要严格识别手拿起，需要后续手部关系建模与实际标注数据，必要时增加深度信息。
